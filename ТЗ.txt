ТЕХНИЧЕСКОЕ ЗАДАНИЕ
на разработку и доработку программного обеспечения «РБД Управление недвижимостью» (Версия 3.13)

1. Общие сведения о системе
- Наименование проекта: «РБД Управление недвижимостью» (настольное приложение на базе PyQt6).
- Цель создания: Автоматизация учета объектов недвижимости (аренда и продажа), ведение единой удаленной базы данных, прикрепление мультимедийных материалов (фото и видео) с жесткими лимитами по объему, разграничение прав доступа операторов и администраторов, а также обеспечение возможности дальнейшей интеграции с Telegram-ботом.
- Стек технологий: 
  * Язык программирования: Python
  * Графический интерфейс: PyQt6
  * СУБД: PostgreSQL (удаленный хостинг)
  * Шифрование и безопасность: bcrypt, psycopg2, ssl

2. Архитектура и структура базы данных (PostgreSQL)
Система работает с удаленной базой данных PostgreSQL, содержащей следующие ключевые таблицы:

2.1. Таблица ads (Активные объявления):
- id (SERIAL, Primary Key)
- ad_number (VARCHAR(50), Unique) — Номер объявления.
- category (VARCHAR(50)) — Категория («Rent» / «Sales»).
- property_type (VARCHAR(50)) — Тип недвижимости («Apartments» / «Houses»).
- rooms (VARCHAR(20)) — Количество комнат (от 1 до 5).
- district (TEXT) — Район.
- landmark (TEXT) — Ориентир.
- area (REAL) — Площадь (для домов).
- floor (INTEGER) — Этаж.
- floors_total (INTEGER) — Этажность.
- price (REAL) — Цена.
- is_active (INTEGER) — Флаг активности (1 — активно, 0 — удалено).

2.2. Таблица archive_ads (Архив удаленных объявлений):
- Дублирует структуру таблицы ads с добавлением поля deleted_at (TEXT) для фиксации даты и времени переноса в архив.

2.3. Таблица users (Учетные записи сотрудников):
- id (SERIAL, Primary Key)
- username (VARCHAR(50), Unique) — Логин.
- password (VARCHAR(255)) — Хэш пароля (bcrypt).
- role (VARCHAR(20)) — Роль в системе (operator / admin).

2.4. Таблица ad_media (Медиафайлы объектов):
- id (SERIAL, Primary Key)
- ad_number (VARCHAR(50)) — Связь с объявлением.
- file_name (TEXT) — Имя файла (изображение/видео).
- file_data (BYTEA) — Бинарные данные файла, хранящиеся непосредственно в базе данных для быстрого доступа.

3. Функциональные требования и бизнес-логика

3.1. Авторизация и роли пользователей
- Обязательное окно входа при запуске программы.
- Проверка подлинности паролей через криптографическое хеширование (bcrypt).
- Разделение интерфейса:
  * Операторы (operator): Доступ к созданию, редактированию, просмотру объявлений и прикреплению медиафайлов.
  * Администраторы (admin): Расширенный доступ через вкладку «Инструменты (Tools)»: управление учетными записями операторов, просмотр системных логов, управление архивом и полная очистка БД.

3.2. Интерфейс и навигация
- Главное окно: Разделено на две основные панели — левая часть (вкладки по категориям, типам недвижимости, комнатам и строка быстрого поиска) и правая часть (панель ввода данных).
- Категоризация: Иерархические вкладки «Аренда» / «Продажа» -> «Квартиры» / «Дома» -> от 1 до 5 комнат.
- Строка поиска: Фильтрация записей в таблицах в реальном времени по введенному району или ориентирy.
- Горячие клавиши: Поддержка быстрого заполнения полей из буфера обмена (Ctrl + V).

3.3. Правила работы с мультимедиа (Без конвертации)
- Запрет конвертации: Автоматическое сжатие или конвертация видеофайлов полностью исключены для сохранения исходного качества и предотвращения потери данных.
- Лимит размера файлов: 
  * Прикрепляемые файлы проверяются на суммарный размер.
  * Если суммарный объем выбранных файлов превышает 50 МБ, программа прерывает процесс и выводит модальное диалоговое окно с предупреждением об ошибке и требованием к оператору уменьшить размер файлов или заменить их.
- Индикатор прогресса и скорости: Процесс загрузки на сервер сопровождается статус-баром с расчетом скорости передачи данных (МБ/с) в реальном времени.

3.4. Встроенный Медиа-просмотрщик
- Вызывается двойным кликом (Double Click) по колонке «Медиа» в таблице объявлений.
- Обеспечивает просмотр фотографий и воспроизведение видео (встроенный плеер с кнопками управления).
- Локальное кэширование файлов во временную папку операционной системы (префикс rbd_media_cache_ в каталоге Temp) с автоматической полной очисткой при корректном выходе из программы.

3.5. Системный мониторинг и логирование
- Все действия пользователей и критические ошибки фиксируются в локальном файле журналов actions.log.
- Реализована фоновая отправка лог-файла разработчику (с защитой от частой отправки — не чаще одного раза в сутки).

4. Требования для интеграции с Telegram-ботом в будущем
Поскольку база данных PostgreSQL хранит всю актуальную информацию об объектах, архивных записях и бинарные медиафайлы (BYTEA в таблице ad_media), проектируемый Telegram-бот сможет бесшовно использовать ту же самую базу данных со следующей логикой:
1. Поиск и выдача объектов: Бот отправляет SQL-запросы к таблице ads по критериям пользователя (район, комнаты, цена, тип сделки).
2. Выгрузка медиа: Бот извлекает бинарные данные (file_data) из таблицы ad_media по номеру объявления и отправляет их клиентам в мессенджер в виде фото или видео галерей без необходимости серверной конвертации.
3. Синхронизация: Любое изменение, создание или удаление объекта оператором в десктопном приложении мгновенно отображается в поисковой выдаче Telegram-бота.
